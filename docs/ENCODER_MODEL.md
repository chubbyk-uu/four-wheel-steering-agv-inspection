# 轮径残差与物理编码器采图

## 当前模型

实际轮胎直径与系统标定轮径分开。`actual_wheel_diameter`启动参数仅改变四轮视觉、接触碰撞尺寸及固定质量下的惯量；默认0.40 m，小范围试验允许0.38–0.42 m。关节安装点、悬挂、轮毂和18 kg单轮质量不变。重新启动即可换径，不动态替换正在接地的轮胎。

`platform.yaml`的`wheel_radius: 0.2`仍是控制器、里程计及相机纵向换算使用的标定半径，不能为了试验同步改成实际半径。物理车身沉降和相机离地高度由接地/悬挂自然决定；这会附带很小的横向成像尺度变化，因此纵向尺度对照不能假定其它像素完全相同。不模拟充气轮胎局部变形，也不额外注入滑移。

相机默认接左前轮轴端编码器：2000 PPR、AB四倍频8000计数/圈。`linescan.yaml`的`wheel_encoder`可手填轮位、PPR、乘数和除数；当前乘数64、除数149，每圈平均3436.241610738行。非整数余量跨圈、跨完整帧及普通停车保留，不逐圈取整。每行间隔由轮角相位交叉时刻插值，不模拟电气波形、具体厂商PLL或额外的整数计数量化抖动。默认参数不代表某一DALSA型号已确认的硬件配置。

固定乘除系数下，无论实际轮径多少，每圈触发行数相同。标定纵向行距为：

`2π × calibrated_radius / (PPR × decode × multiplier / divider)`

默认0.3657010198 mm/行，4096行对应标称1.497911377 m，10 km/h的标称轮速下约7595.76行/s。横向仍4096像素/1.5 m；整数乘除比的已知近似误差约−0.139%，不要与未知轮径残差混为一谈。`line_spacing_m`在新配置中是派生缓存，启动器、C++插件和任务预算从上述参数计算；旧归档无`wheel_encoder`时保留原来的理想距离语义。

## 使用

```bash
ros2 launch agv_bringup sim.launch.py actual_wheel_diameter:=0.39 \
  linescan:=true linescan_backend:=optix scene_manifest:=/path/to/manifest.json
```

保持速度指令与编码器参数相同，分别用0.39、0.40、0.42 m采同一段带横向标识的路面。0.39 m轮胎在相同真实路程内转得更多，原始图像的物体占据更多扫描行；0.42 m反之。预期相对0.40 m基线纵向倍率分别为1.025641和0.952381。没有事后拉伸原图来伪造这种效果。

由于控制器仍使用0.40 m，开环相同轮速/持续时间不等于相同真实路程；比较必须找到同一地面标识，不能只比较总行数或运行时长。使用同一图像显示比例才能肉眼比较，不把每幅图分别缩放到相同高度。

## 采集协议及边界

- C++ render/CUDA/OptiX后端支持。旧Python analytic后端明确拒绝新编码器配置，避免假称物理编码器。
- 四轮运动拟合只做合法扫描状态检查；采图触发读取指定单轮轴角，不再使用四轮平均/车体X投影。转弯时指定轮真实走的弧长与车体中心不同，这是该传感器的正常特征。
- 普通暂停保留触发相位和未满4096行的缓存；结束/取消/故障仍走原尾图规则。位置模式反向回退不重复输出，恢复超过旧计数前沿才继续。
- 正向/反向扫描均可从静止建立相位；元数据`scan_direction`仍表示车体前后方向。一个采集段内若指定轮转向跨过轴向正反分支，触发`unsupported_scan_motion`关闭该段，不能默默停止出行或把反向计数伪造成连续前进。此工况需要新采集段/补扫；本轮不宣称旧长程限位恢复的无缝协议在新传感器上已验收。
- 每图`wheel_encoder`记录PPR、倍频、乘除、每圈行数、标定轮径和`actual_diameter_m_truth`；最后一项仅供仿真评估，后处理不能拿它消除本应未知的尺度误差。`encoder_distance_m`是标定轴弧长，不是真实地面距离。
- 物理轮径变化会改变机器人资产签名及真实相机高度。旧图像标定文件不得绕过兼容检查强行用于新资产；本轮先比较原图，后续需要重新评估固定标定残差和校正适用范围。

## 验证

回归覆盖轮胎几何/惯量与标定控制参数分离、正反转累计149圈的512000行、停车相位保持、纯滚动同一米路程不同原图行数、非法乘除系数及任务尾图预算。实际OptiX三轮对照已完成，见[报告](../results/encoder_diameter_comparison.json)：同一禁停区两横边中心间距0.39/0.40/0.42 m分别为9255/9024/8594原始行，即+2.5598% / 0 / −4.7651%，与理论+2.5641% / −4.7619%吻合。未使用导航位姿调整像素；共同显示尺度、仅对齐第一条横边。对比图和21张原图保留于忽略目录`local_data/encoder_diameter_comparison/`。

三轮均最终HOLD，归档与ROS像素逐字节一致。0.39 m包含GUI/RViz、同步TF/预览及同一4096行帧跨普通暂停检查；未重做鼠标交互，也不代表100 m/10 km/h新模型重验收。标准colcon两包299项零失败，定向Python207项、C++采样13项通过（这些计数有重叠，不相加）。

## 正式巡检入口的换径实验

`inspection.launch.py`同样支持`actual_wheel_diameter:=0.39`（默认0.40）；
`tools/validate_operator_session.py`使用`--actual-wheel-diameter 0.39`，另一组传`0.41`。
该工具在启动前保存`experiment_parameters.json`，归档图块另有实际轮径真值字段。
参数沿巡检入口传给仿真，不修改`platform.yaml`的标定半径0.2 m，也不重标编码器行距。
只改物理轮径仍会改变负重后的相机高度，39/41 cm对照须分别评价纵向与横向尺度。
