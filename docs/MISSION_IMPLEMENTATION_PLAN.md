## 1. 矩形任务及扫描路径规划

已建立agv_mission，提供可独立测试的规划核心和CLI/YAML入口。输入：任务ID、坐标系、起始角点、长度、宽度、固定行距、扫描速度和可行驶区域；长度沿道路+X，不要求用户输入方向角。道路坐标到map的变换由地图配置提供，不能默认任意map的+X都是道路方向。

输出区分采集区域、相机扫描线、底盘参考路径和非采集转场段。路径点从首版包含XYZ、姿态、地表法向/切向、弧长、段类型与扫描方向；当前合法地表模型为已知平面，后续可替换三维地表接口。地面车辆不接收独立升降指令。

按校正后有效幅宽或当前明确声明的名义幅宽计算轨迹数，处理宽度不足一幅及边缘误差余量。用户本轮明确采用固定1 m间距，不自动均分缩小；轨迹组居中覆盖区域。1.5 m幅宽、4 m宽区域生成4条、间距1 m，总幅宽4.5 m，两侧各多覆盖0.25 m；额外覆盖必须通过光学和行驶边界检查。

相机前置1.15 m必须纳入扫描线→底盘变换；掉头180°会使扫描线相对同一底盘中心移动2.30 m。当前换行先前向驶出足够距离，再停车、横移、原地旋转180°，直接对接下一道起跑点；禁止掉头后后退补偿。相机偏置在驶出距离中一次计入。顺逆转结合限位、实际轮组状态和扫掠空间选择。

校验无效尺寸、越界、空间不足、限速、首末扫描边界、转场/制动包络；不静默缩短用户采集区域。首版使用保守平面扫掠包络，不宣称动态障碍规划已完成。

交付：任务YAML、CLI载入/保存、规划结果、RViz区域/轨迹/足迹预览。验收：独立几何测试覆盖窄区、非整除宽度、正反方向、端点及外参偏置；预览通过后再允许执行。

## 2. 测量、外参与三维融合定位

已建立agv_localization适配包，复用robot_localization滤波器。先检查/补齐依赖，再实现传感器接口：

| 输入 | 初始接口目标 | 说明 |
|---|---|---|
| 四轮驱动与转向反馈 | 100 Hz轮里程计，保留vx/vy/wz | 实际编码器增量，考虑轮组几何及噪声/零位 |
| IMU | 100 Hz角速度/加速度 | 不用真值绝对yaw冒充IMU测量；加速度融合另作重力/杆臂验证 |
| RTK位置 | 10 Hz，ENU每水平轴σ=2.5 cm、垂直σ=4 cm | 精度口径已记录，含独立时序/质量状态 |
| 双天线相对基线/航向 | 10 Hz | 基线1.10 m，航向误差由相对解和安装残差传播 |

双滤波结构建立连续局部odom与全局map位置；明确map→odom→base_link唯一发布者、ENU/航向约定、IMU静止初始化、双天线有效性与相位中心杆臂。滤波从首版使用三维状态，平面只是初始地表，不把two_d_mode作为最终架构。

必须分离实际安装T_true与算法标定T_hat：双天线共同支架＋各相位中心、相机六自由度安装、IMU安装、轮组位置/转向零位；C8外参同步配置，点云融合验收沿用。安装误差每次试验固定，支架振动不做。传感器生成/光学成像用实际安装，算法/生产TF及位置标签只用标定安装；真值档案仅供独立评价。

依次验证：零测量噪声/零外参误差 → 单项测量噪声与延时 → 单项固定外参残差 → 组合工况。外参档位、协方差与未知接收机精度按[误差设计](LOCALIZATION_NOISE_BASELINE.md)执行，不把拟定档位当作真机精度。不得假定EKF能自动标定未知外参。

交付：测量节点、噪声/时序/安装配置、双EKF启动、导航轨迹归档及独立误差报告。验收：静止初始朝向、前后/横移/旋转、时间戳/延迟、失锁与恢复；算法链路无真值订阅。正式数值门限在零噪声和独立误差统计后冻结，不能只以曲线平滑为通过条件。

## 3. 时间轨迹与底盘闭环

先独立验证单段直行、横移、旋转，再接完整任务。由路径构造不对称梯形/三角形速度曲线，参考加速度0.8、参考减速度`trajectory_decel=0.8` m/s²，底层物理减速度上限仍1.0 m/s²，保留反馈制动余量，并使用各段限速。短段自动降低峰值速度，不能为了达到10 km/h越过端点。参考采用仿真时间，硬件看门狗采用单调墙钟。

以融合位姿计算沿轨、横轨、航向误差，前馈＋反馈输出车体TwistStamped，经现有底层控制器执行。误差在局部地表切平面内计算，3D位姿保留；高度/roll/pitch由接触决定。四转四驱保留vy，不能照搬差速控制。速度与转向变化要同时满足轮组限位/转速/对轮条件。

底层进入BRAKE/ALIGN时，上层参考应暂停或重新定时，禁止持续推进时间表后突然追赶。段结束同时检查位置、角度、实际速度和停稳状态；不是时间到即成功。小幅纠偏是否仍满足线阵采集条件必须联合测试，不能放宽门限掩盖真实横移畸变。

交付：可独立运行的时间轨迹跟踪器、参数和误差诊断。验收：给定初始偏差、扰动、减速/停车、控制反馈过期、轮组重配与恢复；先0.5 m/s，再提高速度。记录参考/估计/独立真值三条轨迹，后者不参与控制。

## 4. 任务状态机与相机联动

任务状态：IDLE→VALIDATING→READY→RUNNING，以及PAUSING/PAUSED、CANCELING、COMPLETED、FAULT。运行段：入轨、停稳对轮、加速扫描、越过扫描终点、制动、横移、制动、原地180°旋转、下一轨入轨。必要入轨调整属于规划结果，不固定成只有两条速度指令。

单独改造现有采集门：不能只凭motion==DRIVE决定采集。正常端部在扫描线越过采集边界后关门；暂停制动时，只要仍在有效扫描运动中，就继续编码器触发到停稳。异常丢失扫描能力必须报告缺口，恢复后安排补扫，不把行号连续当成物理地面必然无缺口。

换行/旋转不采图；每条轨迹独立段ID，默认不足1000行尾图丢弃图像并记录全局行号范围，达到阈值才按真实行数归档；普通暂停保留缓存，真实长行间隔两侧补充相邻行标签。恢复任务检查当前位置、已采覆盖和已有图块，不简单重复开始整条，也不静默覆盖文件。速度参考不作为行触发距离来源。

图块记录任务/轨迹/段ID、全局行号、首末时间、末行位姿和少量中间标签；导航轨迹按固定频率另档。生产标签由融合位姿＋标定外参计算，不用真值替代；允许显式标记的真值评价标签单独归档。原图保持Mono8与线性响应，不在线校正。

交付：CLI开始/暂停/恢复/取消、状态机、采集门、可追溯会话档案。验收：首末边界、加减速、换行、暂停制动、恢复、取消/断联、尾图落盘、行时间连续性、ROS与档案字节一致；采集结束必须等待归档确认；ACQUIRED仅表示采集流程结束，须另做有效覆盖审计和必要补扫才能认定区域完成。

## 6. 100×10 m全区域采集与稳定性验收

进展（2026-09-10）：完整紧凑场景与11 kHz独立采样已通过，旧展开资源直接删除。载入/实时率优化两轮100×2 m GUI对照为约34秒/0.9988～0.9992，144张固定轨迹原图优化前后逐字节相同，280项测试通过，详见[性能报告](../results/full_road_performance.json)。这仅解除资源与性能的部分阻碍，下列全宽、速度档、重复和异常门槛仍须逐项完成；临时加载器实验发生的掉头后方向变化故障需纳入长时回归，不作为通过结果。

这是进入正式拼接前的必经阶段，目前未通过。按以下顺序执行：

1. **预算和生成完整场景**：100 m长、10 m宽是要求采集的区域，不是整个世界边界。额外设置加速、制动、横移、车体旋转及畸变幅宽所需的非采集缓冲区；由当前车体/相机包络、定位误差和参考加减速度计算，不默认现有约1 m光学裙边足够车辆掉头。保持GZ/RViz低清显示和OptiX高清按需加载，先核对颜色＋法线、精细几何/碰撞代理、BVH、输出、临时文件及多次试验档案的磁盘/内存/显存预算，再生成。旧约60.6 GB纹理估计仅作参考，不能代替包含新缓冲区和采集输出的预算；历史依据见[大场景计划](archive/stage2/STAGE2_TEXTURE_PLAN.md)。
2. **完整区域低速闭环**：1 m行距，轨迹数和两侧余量由规划器计算；验证前后扫描边界、道路两侧、非采集转场、禁止PASS倒退、定位和图像归档。区分未拍到、按策略丢弃尾图和定位不确定度导致的未确认覆盖，实跑补扫并合并报告；不能降低协方差或静默裁短区域来通过。
3. **逐档提速和长时负载**：依次验证0.5、1.0、2.0、2.778 m/s；0.8 m/s已有小区域回归保留。每档均须通过当前空间检查，统计冷启动预热、跨块预取、缓存逐出重载、队列、行时序、落盘、实时率和进程/GPU资源；不能用短程高速或只跑100 m中央走廊代替全宽任务。
4. **异常与交互回归**：覆盖加速、扫描、减速、横移、旋转阶段的暂停/恢复/取消，定位超时/失锁、相机异常分段与关闭失败、重复载入/准备/执行、GUI跟车/缩放和RViz预览。错误须明确报出并受控停车；普通暂停不清空未满帧，故障不静默续跑或误报完成。自动绕障不在此无障碍采集验收内，故障停车必须可用。
5. **重复运行与缺陷关闭**：修复问题后重跑对应场景及受影响回归，记录版本、配置、噪声种子、原图/标签证据和最终停车状态；不能只靠一次演示或单元测试宣布稳定。
