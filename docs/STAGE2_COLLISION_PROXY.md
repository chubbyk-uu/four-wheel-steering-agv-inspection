# 裂缝碰撞简化

> 历史实验记录：本文参数、性能和“当前/默认”描述属于当时版本，不作为新版验收。现行550 kg、20 mm/4K/1.5 m、1 m轨迹间距、11 kHz目标见[当前模型基线](LARGE_AGV_REBUILD.md)。历史命令须按现行配置调整，旧16 mm标定不可用于新版；大体积实验资产可能已清理，复现需重新生成。

2026-09-08。用户已认可新版分叉外观，并要求检查是否可省略毫米级沟槽的精细碰撞。当前目标是路面巡检成像；裂缝三维结构仍参与相机成像和补光阴影，轮胎不需要解析裂缝内部微小接触。

## 官方依据与实现

Gazebo Harmonic的[网格优化说明](https://gazebosim.org/api/sim/8/model_and_optimize_meshes.html)建议视觉使用细节网格、碰撞使用更简单的形状；[SDFormat说明](https://sdformat.org/tutorials/specification/spec_shapes/)也明确允许两者不同以降低碰撞检测成本。这支持分离表示，不代表任何碰撞简化都自动具有足够物理精度。

本轮保持Concrete047A颜色＋法线、所有裂缝沟槽和光照参数不变，仅将5×5 m试片的轮胎碰撞面改为原地面高度的两三角形矩形。视觉/OptiX仍读取355,562个三角形的原网格。不同于取消地面碰撞，车辆仍有支撑与摩擦；不再计算轮胎进入1–2 mm细裂缝内部的接触。

`assets[].collision_proxy`显式记录碰撞资产、哈希、近似策略及深度上限。旧场景没有这个字段时仍要求视觉/碰撞共用原网格；不是全局放宽场景真值校验。

- 当前试片最大几何偏差2 mm，近似填平的凹陷面投影面积占全地面约0.03283%。
- 校验原网格为向上的矩形高度表面，碰撞矩形与其XY范围、高程一致，不允许平移、缩放或偷偷扩大地面。
- 工具默认上限2 mm，策略硬上限3 mm；只允许稀疏浅凹陷，受影响投影面积不超过1%。这些是本项目的保守使用范围，不是物理精度定理。
- 超出上限的坑、凸起、大片起伏和未声明的碰撞替换会被拒绝。较深破损、台阶、坡面或影响轮组运动的几何仍需单独保留与验证，不能用此工具一律填平。
- 当前生成工具只处理单一地面资产。支持后续逐块设置碰撞代理的场景字段，不声称已经完成100 m整路迁移。

## 对照方法

同一轨迹先分别用两个场景的生产OptixScene采集4096×8192像素，16点条光、三次曝光、20 µs，关闭噪声和PRNU隔离影响。核对光学网格、纹理哈希及全部像素一致；碰撞代理不进入成像器。

整车使用正式四点条光和噪声，0.5 m/s、2.1 m、编码器触发、默认4096行图块。按精细GUI、简化GUI、精细无GUI、简化无GUI顺序测试，GUI均含RViz和D3D12。沿用控制器换向/制动状态机，不用真值操纵车辆；真值/显示TF仅用于评价。每次结束零速HOLD并关闭进程。

这是局部短程验证，不能替代10 km/h、100×10 m的持续采集或11 kHz全链路验收，也不评估轮胎变形、微振动或裂缝内部接触力。

## 本轮结果

| 同一新版分叉场景 | 精细碰撞 | 两三角形碰撞 |
| --- | ---: | ---: |
| GUI＋RViz实时率 | 0.8179 | 1.0002 |
| 无GUI实时率 | 0.8399 | 1.0004 |
| 碰撞三角形 | 355,562 | 2 |
| 成像三角形 | 355,562 | 355,562 |

只替换碰撞面即恢复实时，因此本场景先前回退主要来自精细地面碰撞处理；没有进一步细分到某个物理库的内部函数。四次扫描均连续，ROS接收与归档逐字节一致，末尾HOLD并关闭。固定轨迹下4096×8192图像的所有像素一致，裂缝深度、外观和补光遮挡不变。真实车辆轨迹可能因接触近似产生微小变化，不能把固定轨迹像素一致扩大为任意两次整车采集逐像素相同。

21项共享场景测试通过，新增检查覆盖显式代理、深坑/凸起、边界错位、宽松深度参数、缺少声明和校验值篡改。统计见[本轮记录](../results/stage2_collision_proxy.json)。

额外GUI复测使用位姿自身时间戳归一化速度，避免异步显示TF的首末采样时间差被误判为走行差异：精细版平均前进速度0.500000443 m/s、简化版0.500000000 m/s，GUI实时率分别0.8170与1.0004。精细版评价窗口内车体高度变化约1.675 µm，轮心最大单步变化约1.370 µm；简化版接近数值零。本仿真短测中走行影响很小，不代表真实轮胎的同等测量精度，也不评估接触力细节。

当前推荐使用简化碰撞版本：`assets/road/baked_branch_collision_v1/manifest.json`。精细版保留用于光学/接触诊断，正式100 m道路尚未迁移；后续全宽烘焙按这项分离策略处理毫米级裂缝。

## 复现

先按[分叉试片文档](STAGE2_BRANCH_CRACK.md)生成精细版本，然后执行：

```bash
python3 tools/simplify_road_collision.py \
  --scene assets/road/baked_branch_crack_v2c/branched/manifest.json \
  --output assets/road/baked_branch_collision_v1
bash tools/with_optix_runtime.sh bash -c '
  source /opt/ros/jazzy/setup.bash
  source install/local_setup.bash
  python3 tools/validate_collision_proxy.py \
    --detailed assets/road/baked_branch_crack_v2c/branched/manifest.json \
    --proxy assets/road/baked_branch_collision_v1/manifest.json \
    --output /tmp/agv-collision-proxy-check
'
```

输出目录必须不存在；原始精细试片不修改，大纹理不重复烘焙。包装脚本仅用于项目实验性WSL运行库；普通Linux正确配置原生OptiX运行库后可直接执行ROS环境内的Python命令。
