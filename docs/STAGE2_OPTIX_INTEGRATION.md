# OptiX 正式采集接口与逐曝光动态几何

> 历史实验记录：本文参数、性能和“当前/默认”描述属于当时版本，不作为新版验收。现行550 kg、20 mm/4K/1.5 m、1 m轨迹间距、11 kHz目标见[当前模型基线](LARGE_AGV_REBUILD.md)。历史命令须按现行配置调整，旧16 mm标定不可用于新版；大体积实验资产可能已清理，复现需重新生成。

2026-09-07。新增 `linescan_backend:=optix`，已接入 GZ 插件的编码器触发、三次曝光采样、4096 行图块、ROS 原图和 PGM/JSON 归档。它是可选后端；不把尚未完成的复杂场景联合验收标成通过。

## 几何与时序

静态地面和遮挡物来自已校验的 `scene_manifest`，与 GZ visual/collision 共用 OBJ。机器人几何直接从本次启动交给 GZ 的展开 URDF 导出：固定连杆的视觉几何合并到所属运动连杆，共九组（车体、四个转向架、四个车轮）。箱体精确三角化；圆柱采用 64 边形，半径 0.10 m 时最大径向弦差约 0.1205 mm。光线可见性使用 visual，不把简化的 collision 外形冒充相机几何。

每组建立一次独立 GAS。GZ 每个物理步读取实际连杆世界姿态；按每条线三个曝光样本的时间分别插值平移和旋转。GPU 先进行局部包围盒筛选，再将射线变换到连杆坐标系查询 GAS，选择世界和各连杆中的最近交点。灯光遮挡查询同样使用该曝光时刻的连杆状态，不冻结整批轮组姿态，也不需要逐曝光重建 IAS。

逐曝光连杆变换只存在于有界队列和 GPU 输入中，不逐行归档。每块仍最多五个相机位置标签，参考位置仍是最后一行曝光中点。归档同时保存展开 URDF、机器人光学几何描述和静态场景 manifest；外部 OBJ 资产应按 manifest 哈希另行保留。当前只同步 AGV 九组连杆，尚不自动同步用户运行时另行插入的其他动态模型。

物理步仍为 1 ms；曝光插值不意味着模拟了超过物理更新频率的机械振动。扫描运动许可目前仍沿用原有直行限制，尚未为起伏路面的轮速差、滑移和任意转向扫描重新建模。

## 补光和有效性

四个阴影积分点从展开 URDF 的 `led_link` 固定安装关系导出，位置与 GZ 展示灯条使用同一安装坐标，位于实际 0.60 m 灯条发光面。每次曝光按实际所属连杆姿态变换到世界坐标。因此车体、轮组、地面、屏障和架空板都能遮挡补光。

本后端要求 `radiometry.enabled: true`。亮度仍采用经验条带分布 `LedIrradiance`，乘以四个灯光样本的加权可见比例，并复用曝光、渐晕、PRNU、噪声、满阱和量化模型。这不是灯具实测配光或绝对辐射标定，GZ 展示亮度也不保证与输出 DN 相同。环境项暂为常量；强补光能够压低环境变化占比，但补光本身被挡时不会人为消除阴影。四点对有限灯条阴影的收敛误差仍需专项验证。

成像模型标记为 `optix_relative_strip_v1`，源标定 ID 增加 `-optix-strip-v1`，使旧平面 CUDA 平场文件在兼容性检查中被拒绝。地面暂为程序网格，其他静态物体为常量漫反射、车体使用 URDF 灰度颜色；真实水泥纹理尚未接入。

任一像素的任一曝光主射线缺失时拒绝整批，不发布残缺积分形成的暗像素。此阶段要求地表覆盖相机视野，未定义合法天空背景。噪声使用显式采集行号；预热不消耗行号。沿用按行数/任务数/最长等待有界的队列及失败后显式重建服务；当前 OptiX 的缺失样本通过单元测试，整车数据故障恢复测试仍来自上一轮 CUDA 后端，不混称为 OptiX 故障注入测试。

## 验证范围

详见 `results/stage2_optix_integration.json`。新增测试使用具有独立解析结果的移动黑色平面，验证平移、旋转、曝光内切换遮挡、有限灯条阴影、实际灯具附件运动、单次曝光缺失和预热/分批噪声一致性。机器人导出测试验证固定变换烘焙、移动关节不重复烘焙、法线方向、发光面位置和不支持几何时显式拒绝。

整车正向/倒车低速测试检验原图 ROS 接收、块间连续编号/距离、末行参考时间和最终 HOLD。图像预览见 `docs/linescan_optix_gz_preview.png`。三维场景不沿用旧平面网格投影公式作为几何真值；几何交叉验证见共享场景记录，动态算法使用上述独立解析测试。

20 km/h 起伏地面测试触发了旧直线扫描保护，不能通过连续采集验收。触发时 `events.jsonl` 记录四轮速度、轮速差、最大转角、编码器航向角速度估计和相应门限，便于区分运动许可问题与 GPU 采样失败。没有放宽门限，也没有把不连续段拼成连续图像。

采样速率只包含姿态打包、GPU 上传、求交、辐射和读回，不包含所有物理、ROS、归档和校正成本。当前共享网格全部常驻 GPU，未接入纹理或 BVH 分块流式加载。本节早期整车测试为 headless；后续已完成 [10 km/h 平地 GUI＋RViz 对照与显示修复](STAGE2_FLAT_GUI_10KMH.md)。当前尚未做 OptiX 新平场标定、校正订阅者与 fsync 并行的 11/22 kHz 完整验收。

### 本轮实测摘要

55 项包测试通过（0 错误、0 失败、0 跳过）；静态网格 200264 个三角形，机器人 3616 个三角形。

- 正向 0.15 m/s、1.3 m：4439 行（4096+343），实时率 1.00016，采样阶段约 61936 行/s，队列峰值 3 行；ROS 两块均接收，最终 HOLD。
- 倒车 -0.15 m/s、1.3 m：4438 行（4096+342），实时率 1.00016，采样阶段约 64078 行/s，队列峰值 2 行；ROS 两块均接收，最终 HOLD。
- 最终高速诊断：20 km/h 指令、30 m、起伏地面，122 次运动许可拒绝，97788 行、127 个归档块，实时率 0.96256。轮速差最高 0.08112 m/s（门限 0.01），编码器偏航估计绝对值最高 0.07375 rad/s（门限 0.02）。采样批次最大 6.129 ms，等待队列峰值 114/2048 行，最长等待 5.197 ms，无采样溢出事件。ROS 测试订阅者收到 125 块，未收到归档块 67、114；除断段外，接收完整性也不合格，需验证消费队列和交付确认机制。最终已 HOLD。

采样阶段的约 6.2 万行/s 不能替代连续采集、实时率和交付验收。所有高速未通过结果均保留，不只记录成功子项。

## 复现

构建会在 SDK 存在时启用 OptiX；可通过 `-DAGV_OPTIX_SDK=/path/to/sdk` 指定，或 `-DAGV_ENABLE_OPTIX=OFF` 关闭。已在独立构建/安装目录验证无 CUDA 构建及其测试通过（摘要见结果 JSON）。无 CUDA 构建使用 `-DAGV_ENABLE_CUDA=OFF`，保留 GZ 参考和 Python 路线，不承诺它们具有实时全保真吞吐。

先运行 `python3 tools/generate_shared_scene.py --output /tmp/agv_flat_scene` 生成新的水平网格基准。旧 `/tmp/agv_shared_scene_v2` 仍为起伏光学夹具，不用于当前行驶验收。

WSL 继续使用已经验证的实验性进程隔离运行库，无额外安装和系统驱动修改。先在隔离环境内加载 ROS 环境，以保留 ROS 动态库搜索路径：

```bash
bash tools/with_optix_runtime.sh bash -c '
  source /opt/ros/jazzy/setup.bash
  source install/setup.bash
  ros2 launch agv_bringup sim.launch.py \
    linescan:=true linescan_backend:=optix \
    scene_manifest:=/tmp/agv_flat_scene/manifest.json spawn_x:=2
'
```

GUI 默认 D3D12、跟随 AGV。启动并不会自动开车或开启采集；仍使用 `/cmd_vel` 的带仿真时间戳 `TwistStamped` 和 `/linescan/set_enabled`。

当前范围已按用户确认收回到水平路面：允许不影响轮组正常接地与滚动的局部小凹坑和破损，倾斜平面后续考虑，起伏路面暂不考虑。上述高速结果只属于历史光学压力场景，不能作为当前路面验收失败的结论，也不据此修改运动门限。

水平网格路面的 10 km/h 连续采集、ROS 完整交付及 GUI＋RViz 对照已通过，详见上述后续记录。下一步推进有限灯条积分收敛、新标定与联合负载。缺陷加入时需验证其尺寸、深度和布置不会影响轮组，不采用“只改成像几何、碰撞仍为平面”的办法掩盖通过性问题。
