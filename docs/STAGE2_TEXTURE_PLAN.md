# 平地纹理与大场景加载计划

当前4096像素覆盖1.2 m，采样间距0.29296875 mm，仿真最高10 km/h。任务区域100×10 m，保持平地，不引入影响轮组接地的起伏。

## 贴图与纹理

纹理是地表图片等数据；贴图是将数据按UV映射到表面。当前GZ有网格展示图，OptiX使用程序网格，没有真实水泥图片。给GZ加载图片不会自动让OptiX拍到图片。目标是一份纹理资产、一套物理尺寸和UV，两边分别使用适合自身的分辨率，不要求显示RGB与传感器Mono8 DN相同。

纹理只改变反射外观，不自动产生凹坑深度、接触力或遮挡。裂缝/板缝可先用有尺度真值的外观表示；需要几何深度的破损必须由共用几何生成。素材中烘焙的阴影不能当成实际LED产生的阴影，需要选择或处理成近似反射率资产。

## 爬壁机器人已有证据

参考 ../climbot_sim/docs/archive/status-history/STATUS_2026-08-27.md 约1460—1530行：

- 首版估计5.31 GB，打开GUI后WSL两次崩溃；漏算服务端和GUI各自加载场景。
- BC1 DDS与离线mip链降低占用；10×8 m、0.50 mm/像素整墙最终80块，带边框约252 MiB磁盘产物。
- 真实邻域边框解决分块过滤接缝；重叠区/mip逐像素比对。
- 简单重复平铺曾造成全局匹配错误，改用固定种子quilting。
- BC1对拼接匹配的测试不能替代细裂缝保真验收。

## 分阶段实现

1. 用户比较两版样片后，确定使用 ambientCG Concrete047A，已通过代理下载8K无损颜色图并完成10×10 m样片。Gravel保留作对比，旧Brushed版本停用。用户要求5×5 m板块、车道线、0.8—2.0 mm细长裂缝及小破损；缺陷原始外观使用imagegen生成。选材及烘焙结果见 STAGE2_CONCRETE047A_COMPARE.md；源图暂按2.1 m项目尺度映射，非官方实测尺度。
2. 先做约2×2 m试片。OptiX读取三角形UV、材质/纹理引用，在命中位置插值UV并采样纹理对象；GZ读取同源资产。先用无损纹理，验证实际采集图中的细节、坐标、尺度和接缝；自然素材外观不能代替有标签的缺陷真值。
3. 扩展磁盘瓦片与GPU固定容量缓存：异步预取、CPU解码缓存、GPU上传、就绪事件、在用块固定、批次完成后才允许淘汰。按曝光期间整个视野及正反运动预测瓦片，不仅按相机中心。禁止未就绪块以黑色或旧块冒充。
4. 验证100×10 m及更宽场景：冷加载、跨块、正反行、GUI/RViz联合负载。独立11 kHz压力测试不能由10 km/h约9.48 kHz供给替代。

## 初始预算（估算，非实测）

1000平方米、0.29296875 mm/纹素约116.5亿纹素：Mono8约11.65 GB、RGB约34.95 GB；不含mip、边框、GPU展开格式和重复场景。

建议首轮源纹理0.25 mm/纹素（素材需有足够有效细节），4096²每块覆盖1.024×1.024 m。Mono8每块16 MiB，32槽原始纹素512 MiB；边框、上传暂存、BVH、输出、ROS缓冲与GUI另计。缓存大小按实测视野与加载延迟确定。源图RGB转线性亮度需记录颜色空间，不能无条件把照片码值视为线性反射率。

GZ先用同源概览，例如4 mm/纹素：1000平方米按RGBA8展开约250 MB，完整mip约333 MB/场景，服务端和GUI都保守计入。细裂缝在概览里可能不可见，OptiX高分辨率采集仍须保留；GUI近看另加局部细节层及预算，不加载整场最高精度。共享内容与坐标，不代表跨进程共享显存。

记录源图及派生图哈希、像素尺寸、米/纹素、坐标、颜色空间和种子。瓦片边框来自真实相邻内容，各mip从一致源图生成；不靠重复边缘像素或重叠地面几何掩盖接缝。避免无变化重复铺同一张小图影响拼接定位。

有损压缩后置：先验证裂缝宽度、对比度、连通性及检测结果。纹理流式缓存与几何BVH加载是不同问题；首版几何可常驻，纹理分块不必反复重建整场BVH。

本文件是设计，尚未接入真实水泥纹理或OptiX纹理缓存。
