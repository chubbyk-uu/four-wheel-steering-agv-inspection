# 平地纹理与大场景加载计划

当前4096像素覆盖1.5 m，采样间距0.3662109375 mm，仿真最高10 km/h。任务区域100×10 m，保持平地，不引入影响轮组接地的起伏。

## 贴图与纹理

纹理是地表图片等数据；贴图是将数据按UV映射到表面。默认GZ/OptiX场景仍为网格；Concrete047A已在独立沟槽夹具中完成OptiX颜色、法线、粗糙度采样试验，见[材质成本记录](STAGE2_PBR_COST.md)。给GZ加载图片不会自动让OptiX拍到图片。目标是一份纹理资产、一套物理尺寸和UV，两边分别使用适合自身的分辨率，不要求显示RGB与传感器Mono8 DN相同。

纹理只改变反射外观，不自动产生凹坑深度、接触力或遮挡。裂缝/板缝可先用有尺度真值的外观表示；需要几何深度的破损必须由共用几何生成。素材中烘焙的阴影不能当成实际LED产生的阴影，需要选择或处理成近似反射率资产。

碰撞优化已完成局部验证：原精细分叉GUI实时率约0.82、无GUI约0.84；只替换为显式水平碰撞代理后均恢复约1.00，成像像素在固定轨迹下相同，见[碰撞简化记录](STAGE2_COLLISION_PROXY.md)。接下来按成像精细、碰撞有界简化的策略扩展全宽，仍需大场景性能验收。

20×10 m全宽短路段及两条相邻正反向原图采集已通过，包含GUI＋RViz和边缘视野试验；按用户最新要求，下一步先做矩形区域规划、融合定位、time任务控制和RViz输入，任务采集通过后再做离线校正/拼接及TIFF输出，详见[全宽道路记录](STAGE2_FULLWIDTH_ROAD.md)。

1. **细长分叉裂缝样片**：用户反馈当前裂缝像刀刻，主线过于规整、边缘利落、分叉不足。继续用imagegen生成原始裂缝外观，不以程序随机画线替代。保留Concrete047A底纹，制作约2×2 m局部试片；主裂缝细长，加入少量不规则细分叉、局部宽度变化、边缘细碎破损及积灰，避免密集龟裂或粗黑描边。缺陷宽度约束仍为0.8–2.0 mm，分叉不擅自扩大此范围；生成图本身不作为毫米尺度真值，提取轮廓、映射物理尺度后须测量核对。
2. **外观与沟槽一致性**：从同一裂缝轮廓派生反射率、局部法线和沟槽，分叉位置一致；沟槽边缘及深度适度变化，避免整条固定截面的机械刻槽。先保持现有毫米级深度预算，不引入影响轮组接地的凹陷。将反射率变化与烘焙阴影分开，避免素材阴影和OptiX补光阴影叠加造成黑描边。
3. **局部实拍与成本复核**：用相同曝光、补光、显示转换采集旧版/新版对照及1:1裂缝裁剪，核对宽度、分叉连通性、跨瓦片接缝和GZ/OptiX几何对应；报告新增三角形、显存和批次耗时，再做11 kHz采样回归。先给用户看实际传感器样片，确认外观后才替换整路资产；生图效果图不能代替仿真采集结果。
4. **全宽与相邻轨迹**：外观确认后，先做较短的全10 m宽路段，再扩展100 m；补齐边缘视野余量，继续使用有界缓存。随后验证两条有侧向重叠、含正反向运动的扫描轨迹及离线拼接，同轨迹图块不得人为重复末行。
5. **最终TIFF显示输出**：在离线拼接阶段实现，当前按用户要求暂缓。线性处理与供查看的亮度转换分开，详见[离线校正文档的待办](STAGE2_CONCRETE_CORRECTION.md#待办最终拼接与tiff显示输出)。

## 初始预算（估算，非实测）

历史初估按0.29296875 mm/纹素为116.5亿纹素。当前实际烘焙0.25 mm/纹素，1000平方米为160亿纹素：Mono8约16 GB、RGB约48 GB；不含mip、边框、GPU展开格式和重复场景。

建议首轮源纹理0.25 mm/纹素（素材需有足够有效细节），4096²每块覆盖1.024×1.024 m。Mono8每块16 MiB，32槽原始纹素512 MiB；边框、上传暂存、BVH、输出、ROS缓冲与GUI另计。缓存大小按实测视野与加载延迟确定。源图RGB转线性亮度需记录颜色空间，不能无条件把照片码值视为线性反射率。

GZ先用同源概览，例如4 mm/纹素：1000平方米按RGBA8展开约250 MB，完整mip约333 MB/场景，服务端和GUI都保守计入。细裂缝在概览里可能不可见，OptiX高分辨率采集仍须保留；GUI近看另加局部细节层及预算，不加载整场最高精度。共享内容与坐标，不代表跨进程共享显存。

记录源图及派生图哈希、像素尺寸、米/纹素、坐标、颜色空间和种子。瓦片边框来自真实相邻内容，各mip从一致源图生成；不靠重复边缘像素或重叠地面几何掩盖接缝。避免无变化重复铺同一张小图影响拼接定位。

有损压缩后置：先验证裂缝宽度、对比度、连通性及检测结果。纹理流式缓存与几何BVH加载是不同问题；首版几何可常驻，纹理分块不必反复重建整场BVH。

已完成世界XY投影、GZ同源概览和OptiX颜色＋法线有界流式缓存，100 m中央走廊通过独立11 kHz原图链路验证；任意网格UV与校正拼接整链路仍待扩展；20 m短路段现已完成全10 m宽高精度烘焙及独立11 kHz测试，100 m全宽仍待扩展，见[全宽道路记录](STAGE2_FULLWIDTH_ROAD.md)。见 [流式道路记录](STAGE2_STREAMED_ROAD.md)。

## 100×10 m扩展决策与预算

最终大区域验收需要生成100×10 m全宽道路，但不是启动规划/闭环的前提；先用现有20×10 m验证矩形规划、定位/闭环、采集及固定外参误差；往返照明匹配留至后续拼接阶段。维持GZ约4 mm/纹素同源概览，OptiX使用0.25 mm/纹素颜色＋法线及真实沟槽，不改为将低清GZ图放大。

当前生成器按100 m、光学余量、2048核心/2像素边框、24横向块计算为4800块，R8＋RG8无损纹素约60.634 GB（56.47 GiB），不含网格、预览、采集与烘焙临时文件。GPU纹理32槽约385.5 MiB，长度增加不改变槽数，但全场几何/BVH、GZ服务端与GUI各自资源、CPU与生成过程峰值仍增加；不能把固定纹理缓存解释为整机资源恒定。旧20 m夹具约555.4 MiB显式GPU分配不是整机峰值保证。扩展前保留足够磁盘余量，生成后必须测GUI＋RViz＋雷达＋OptiX、冷热加载/跨块/换向/持续落盘，不提前承诺资源足够或11 kHz通过。
