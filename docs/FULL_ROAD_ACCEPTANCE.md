# 100×10 m场景与采集验收

## 空间和资源预算（2026-09-10）

当前完成预算，尚未完成大场景生成或全区域实跑。可复算入口：

```bash
python3 tools/budget_full_road.py --output results/full_road_budget.json \
  --request src/agv_mission/config/rectangle_100x10.yaml
python3 -m pytest tools/test_full_road_budget.py -q
```

使用现行550 kg/20 mm/1.5 m配置和最高10 km/h计算；规划器复核0.5、1、2、2.77778 m/s，不能以较低速度预算后直接提高车速。

| 范围 | 世界坐标（m） | 用途 |
|---|---|---|
| 采集区域 | x=[0,100]、y=[−5,5] | 完整100×10 m，不裁短 |
| 可行驶区域 | x=[−8,108]、y=[−6.5,6.5] | 前后各8 m、左右各1.5 m实体混凝土缓冲区 |
| 光学/贴图范围 | x=[−9.216,109.056]、y=[−7.68,7.68] | 额外背景裙边，不自动当作可行驶区 |

10条扫描中心线y=−4.5…4.5 m，固定1 m行距。有效幅宽预算扣除每侧0.1 m误差，名义相邻重叠0.5 m、扣误差后0.3 m；这不是实际定位协方差已满足的声明。

最高速加速引入段约4.923 m（含0.1 m纵向余量），中间道前向驶出约7.223 m（含前置相机及下一道起跑距离）。名义车体扫掠x约[−7.573,107.573]、y=[−6,6] m，再计0.1 m跟踪余量及0.25 m建设余量，向上取整到半米。整个采集区的长度仍为100 m。

缓冲区不属于要求覆盖的ROI；当前采集门会从PASS起跑时打开，因此**加速区仍会产生原图**，不能只给缓冲区廉价占位纹理。已检查整条直行段的原始畸变幅宽、相机前置及误差范围仍位于高清域内。换道/旋转不采图。

| 项目 | 预算 | 口径 |
|---|---|---|
| 高清纹理 | 6930块，87.54 GB | 0.25 mm/纹素，R8颜色＋RG8法线，含真实邻域gutter |
| 一次全区原图 | 约11.77 GB | Mono8，包括加速区/关门余量，不含补扫或重复ROS bag |
| 三次采集＋一次全量补扫 | 约47.08 GB | 为反复验收留空间，并非补扫必然这么多 |
| 源图/几何/显示图/临时文件 | 15 GiB预留 | 超过后重估，不静默超预算 |
| 新增磁盘合计 | 约150.72 GB | 不含已有资产；保留额外空闲空间 |
| 高清GPU纹理缓存 | 385.5 MiB | 32槽，大小不随路长增长；不是总显存 |
| GZ颜色＋法线显示图 | 约1.21 GB | 4 mm显示采样、两张RGBA及mipmap的估计，不是实测 |
| RViz显示图 | ≤256 MiB | 每显示分区最长边1024，RGBA+mipmap保守上界 |
| OptiX几何/BVH/构建scratch | 2 GiB预留 | 约800万三角形估算，生成后读真实数值；当前scratch仍保留 |
| 相机/队列/机器人 | 512 MiB预留 | 需长运行测量 |
| 驱动/窗口/GZ及其他图形余量 | 3 GiB预留 | 需与上述明确分配一起测量 |
| 整机GPU工作上限 | 10 GiB | 留出16 GB显卡余量；超限先分析再运行 |
| 主机进程RSS | 生成≤12 GiB、仿真≤20 GiB | 不把可回收文件缓存当作进程泄漏；不同时烘焙和跑仿真 |

本次环境检查空闲磁盘约886 GB、可用内存约30 GiB，GPU总显存约16 GB，静态预算允许继续。容量足够不等于跨块延迟、实时率或采集可靠性通过。预算数据见[JSON](../results/full_road_budget.json)，请求见[100×10任务](../src/agv_mission/config/rectangle_100x10.yaml)。

现有20 m纹理继续用于快速回归。新场景使用独立目录，源材质/AI分叉裂缝不重绘。需要同时接入场景边界与RViz缓冲区显示，防止面板沿用20 m示例边界。完整阶段门槛仍以[实施计划第6节](MISSION_IMPLEMENTATION_PLAN.md#6-10010-m全区域采集与稳定性验收)为准；预算验证不是采集验收。
