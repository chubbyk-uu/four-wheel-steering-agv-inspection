# OptiX 三维线阵成像微基准

> 历史实验记录：本文参数、性能和“当前/默认”描述属于当时版本，不作为新版验收。现行550 kg、20 mm/4K/1.5 m、1 m轨迹间距、11 kHz目标见[当前模型基线](../../LARGE_AGV_REBUILD.md)。历史命令须按现行配置调整，旧16 mm标定不可用于新版；大体积实验资产可能已清理，复现需重新生成。

本测试验证三角网格求交、有限长度条灯的离散阴影采样与吞吐，不是正式传感器或全链路验收。代码在 `tools/optix_scan/`，独立编译，不改变 ROS/GZ 默认后端。

## 场景与成像

- 静态 100×10 m 场景，10 cm 网格剖分，地面约 ±25 mm 起伏，局部增加约 10 cm 深的凹坑；重复放置直立遮挡面与架空遮挡面，共 200040 个三角形。遮挡物不是已建模 AGV 车体。
- 4096 像素，名义幅宽 1.2 m，高度 0.8370535714 m，针孔射线斜率与项目 7 µm 像元、20 mm 焦距对应，使用 `q+0.04q³` 畸变。
- 每行三个曝光时刻，跨度 20 µs，曝光期间前进速度 20 km/h。相邻行距 0.29296875 mm；性能测试不限速生成，沿 x 扫描 96 m 后重复，轨迹重置不是实际车辆掉头。只扫描中间一条带，不声称覆盖整个 10 m 宽地面。
- 主射线用 OptiX 三角形 GAS 求交；命中法线来自三角形，面向相机。10 cm 几何采样只是粗糙起伏，未验证毫米级缺陷几何。
- LED 位于相机前方 0.25 m，名义离地 0.30 m，长度 1.4 m，分别用 1、4、8 个等权发光点近似；每次曝光每个命中点向各发光点追踪可见性射线。单点档只作性能对照。4/8 点的离散半影仍需采样收敛验证。
- 光照采用距离衰减、表面余弦、纵向有限带宽与固定参考平面中心强度 40；环境项 1。不是实测配光；环境项没有太阳方向遮挡。与现有 CUDA 平面超高斯配光不是同一个灯具模型。
- 程序网格作为线性反射率，复用项目 `radiometry.hpp` 的曝光、暗角、PRNU、噪声与 Mono8 响应。基准光学数值显式写在 `shared.h`，没有接入 YAML 配置加载。
- 没有磁盘纹理或瓦片流式加载。场景与加速结构启动时一次上传，未连接 GZ 场景真值或动态变换。

## 正确性与计时

计时前使用独立 CPU Möller–Trumbore 暴力遍历核对 16 个像素，每像素包括三个曝光时刻和四个灯光遮挡检测。CPU 与 GPU 共用光照公式，验证的是求交与阴影链路，不是光度模型物理真实性。检查位置覆盖凹坑、地面和架空面区域，不能代表所有几何边界都经过穷举。

另生成开启/关闭阴影的同轨迹 4096×4096 图像，检查阴影确实改变结果。分别验证无噪声、有噪声时，4096 行一次生成与 256 行分批逐像素相同。随机噪声以显式行号索引，不受预热调用次数影响。

吞吐测量每档 30 秒，不调用节拍 sleep，256 行一批，计时包括参数上传、OptiX 成像、Mono8 读回到 pinned host memory 和同步。包含噪声。启动编译、场景上传/BVH 构建、正确性测试、预热和预览写盘不计入持续吞吐。单批最大值与 P99 一并报告。

不包含 ROS、图块归档/fsync、校正、GZ 物理/控制负载、动态 IAS 更新、纹理采样/加载或场景同步。不能与旧台架包含 ROS/磁盘的 active 指标直接比较，也不能替代 11/22 kHz 完整验收。

## 复现

```bash
python3 tools/generate_shared_scene.py --profile optical_stress --output /tmp/optix_shared_scene
bash tools/optix_scan/build.sh > /tmp/optix_build.log 2>&1
# 输出目录必须尚不存在；实验 WSL 环境见 STAGE2_OPTIX_WSL.md。
timeout 150s bash tools/with_optix_runtime.sh \
  /tmp/agv_optix_scan_build/bench /tmp/agv_optix_scan_build/scan.ptx \
  /tmp/optix_scan_result 30 256 /tmp/optix_shared_scene/manifest.json > /tmp/optix_scan.log 2>&1
```

`report.json` 给出测试数据；`shadow.pgm`、`unshadowed.pgm` 为实际生成的图像。原型是短生命周期基准程序，失败时进程退出释放 GPU 资源，不作为常驻服务使用。

## 2026-09-07 实测结果

环境为 RTX 5080、Windows 616.64、隔离 Linux 610.57.04 运行库、OptiX 9.1、CUDA 12.8。每档持续 30 秒，原始报告见 `results/stage2_optix_scan.json`。

| LED 发光采样点 | 行/墙钟秒 | 256 行 P99 | 最长批次 |
|---|---:|---:|---:|
| 1 | 485870 | 0.956 ms | 5.823 ms |
| 4 | 233562 | 1.732 ms | 2.878 ms |
| 8 | 138649 | 2.593 ms | 3.915 ms |

8 点档约为 22 kHz 的 6.30 倍，但仅是上述驻留场景的成像与读回余量。22 kHz 时 256 行对应 11.636 ms，本次最长批次均小于这一间隔；未模拟 GZ 采样任务队列。

16 个 CPU 核对像素最大差异 0 DN；阴影使 4147575 个像素降低超过 3 DN，最大降低 164 DN。无噪声及有噪声的分批比较均逐像素一致。场景上传与 GAS 构建约 10.91 ms，GAS 约 12.38 MB。测试后 GPU 查询正常，三项系统库 SHA256 均与修改前一致；没有检验 Windows 事件日志，也不代表长期稳定性认证。

图像对照见 `optix_scan_comparison.png`。下一步应共用正式场景资产，补上实际纹理与动态状态，再接入采集/归档链路测整车负载。当前数据足以支持继续原型验证，不能宣布完整 22 kHz 验收通过。

后续变更：当前基准已移除内部地形生成器，强制读取共用场景网格；参见 [共享静态场景](STAGE2_SHARED_SCENE.md)。上述历史持续性能对应此前 200040 三角形场景；新场景包含显式斜坡与实体遮挡物，不能把旧性能数字当作新场景复测结果。
