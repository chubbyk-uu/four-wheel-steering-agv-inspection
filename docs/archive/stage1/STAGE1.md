# 第一阶段：AGV 模型与基本控制

状态：第一阶段保守控制原型的初步功能验收通过。最新构建、22 项 C++ 核心测试（colcon 汇总含 CTest 包装项共 23 项）、ROS 指令边界回归、GZ 基础运动及扩展连续序列均通过。外观图由 GZ Ogre2 实际渲染并检查；尚未实现严格的车体速度联合指令生成器，边界见后文。

沙箱内首次启动因通信套接字权限失败；上述 GZ 和 ROS 验收均来自随后具有主机通信权限的运行，不将沙箱失败作为平台功能结果。

## 模型与坐标

- 总质量默认 65 kg：车体等效质量 41 kg、四个转向机构各 2.5 kg、四轮各 3 kg、相机与 LED 各 1 kg。车体等效质量包含电池和支架等简化部件。
- 车体约 0.90 × 0.65 m，轴距 0.65 m、轮距 0.55 m、轮径 0.20 m；轴距和轮距是转向轴中心间距。
- `base_link` 在车体中心，标称离地高度 0.36 m，x 向前、y 向左、z 向上。
- 轮组顺序固定为 `fl, fr, rl, rr`。转向轴为局部 z，驱动轴为转向后的局部 y。
- 转向实际机械范围 ±190°，目标软限位 ±185°；不会按 ±180°对机械角度取模。
- 转向最大目标速度 1.2 rad/s、加速度 3 rad/s²，轮缘速度变化率默认 0.8 m/s²；横移上限 1 m/s，平移合速度上限 20 km/h，车体角速度上限 0.8 rad/s。
- 相机和灯条安装在前部，包含支架外观和向下的光学坐标系。目前无采集、光源或相机传感器插件；安装高度和光学方案需在第二阶段调整验证。
- 平地世界保留重力和轮地接触；碰撞轮胎采用圆柱体，尚无悬挂、轮胎形变与编码器噪声。

可见装饰部件不逐件创建惯性关节，质量计入所属结构。质量变化由车体等效质量承担，其余模块暂定不变。模型检查覆盖 50、65、80 kg 三个配置。

## 控制结构

```text
/cmd_vel (TwistStamped, base_link)
          ↓
指令时间与数据校验
          ↓
车体速度分配 + 有限角度等价解优化
          ↓                    ↑
BRAKE / ALIGN / DRIVE / HOLD ← /joint_states 实际转角与轮速
          ↓
4 个转向位置目标 + 4 个驱动角速度目标
          ↓
forward_command_controller → gz_ros2_control → GZ 关节
```

控制节点不订阅 GZ 真值。`/ground_truth/odom` 仅由独立评价工具使用，未桥接真值 TF，也未把它伪装成融合 `/odom`。本阶段只有 `robot_state_publisher` 发布机器人内部 TF；全局定位 TF 及轮式里程计属于第三阶段。

## 连续运动与停车转向

每个轮子根据 `(vx - wz*yi, vy + wz*xi)` 分配轮向和轮缘速度。枚举限位内的 `theta + k*pi`，用驱动符号补偿奇数个半圈；代价考虑实际机械转向距离、软限位余量和上次选解的连续性。

直行 0° 位于机械行程中间，左右小角度修正不会遇到端点或取模跳变。±190°硬端点在轮组朝后附近；但由于驱动可反转，±180°同样能实现车体直行，因此仅说明“端点朝后”还不够。静止重新分配时，候选目标必须保留至少 10°软限位余量，在合格候选中主要按最短机械转向选解，并用小幅迟滞与余量代价抑制临界选解抖动。不再对所有停车强加靠近 0°的偏好；零速度指令也不触发无意义回正。

连续运动中保留当前等价分支；用实际转角、转向速度和目标趋势检查软限位余量。向端点运动时，余量应大于 `10° + 转向速度²/(2×转向加速度) + 转向速度×控制周期`。不足时记录 `LIMIT_RECONFIGURE` 并制动；停稳后才将候选限制到中间等价分支。此处没有未来路径预瞄，只使用当前状态和当前目标，因此是保守局部策略，不是全任务最优解。

公开产品资料核对：Honest Edrive HL300 标注 ±180°转向限位，但页面不能确定其装车后的零位朝向。AgileX Ranger ROS 2 `humble` 分支中 Ranger / Mini V2 / Mini V3 的平行运动参数为 1.570 rad（约 90°），这是指令范围，不能推断其硬挡块位置；文件内部分角度注释与数值不一致，以数值为准。没有据此宣称行业统一采用某个机械挡块方位。本项目的直行零位居中及静止选解预留限位余量，是针对无滑环与常用直行工况的设计选择。

| 状态 | 行为与退出条件 |
| --- | --- |
| `HOLD` | 零驱动、保持轮向；新指令到来后开始对轮。若反馈仍有明显轮速则先制动 |
| `DRIVE` | 允许小幅轮向调整，限制转向速度和加速度；统一缩放驱动目标并协调轮速变化 |
| `BRAKE` | 不追随新的轮向目标，先按转向加速度限制停止已有转向运动并保持轮向；驱动目标逐步降至零，实际四轮轮缘速度及指令均低于 0.025 m/s，转向也已减速后才退出 |
| `ALIGN` | 驱动保持零，四轮转到新目标；各轮角误差低于 0.035 rad，实际与指令转向速度差低于 0.08 rad/s、实际速率在限制内，连续稳定 0.10 s 后恢复行驶。允许已稳定跟踪的非零转向速率 |
| `FEEDBACK_HOLD` | 反馈缺失、异常、时间异常时将驱动指令置零，清除旧指令与过渡状态，等待有效反馈及新指令 |

以下情况从行驶进入制动：

- 任一轮实际轮向与目标差超过 0.30 rad，约 17.2°。
- 任一轮实际轮缘速度超过停稳阈值，而新解要求驱动反向。
- 任一轮的 `abs(实际轮缘速度 × sin(轮向误差))` 超过 0.12 m/s。此量是连续切换的保守判据，不是测得的实际侧滑；因此高速时允许的角误差更小。
- 收到零速度、无效指令，或指令超过 0.4 s 未更新。
- 向限位运动且剩余行程不足以保留配置余量及转向制动距离。

小角度连续调整中，对四轮采用统一的余弦误差缩放系数，以及统一的轮速插值比例。这只能协调轮速变化，不能保证独立转向过渡中的四个轮速向量始终精确对应同一个刚体速度。当前原型不等于在车体速度空间联合求解的 Swerve 指令生成器，更不是完整的动力学最优控制；复杂运动下的轮胎擦滑仍须进一步评价。

单轮驱动经过零速不自动要求全车停车。只有反向目标与仍高于停稳阈值的实际轮速冲突时，本阶段策略才保守制动；缓慢经过零速、其余轮子继续运动的序列有单独测试。局部目标轮速低于 0.005 m/s 时保持该轮轮向，避免瞬时旋转中心或微小噪声使角度无意义跳变。

新指令在制动和对轮过程中持续更新；恢复驱动前仍需满足当前目标的对轮条件。仅因转向时间已到，或驱动目标已经为零，不会判定轮组动作完成。

直接后退不需要把舵轮转到 180°。四轮原先为 0°时保持 0°，仅将四个驱动速度变成负值；若此前正在前进，则先减速到零，再反向加速。该过程可能经过状态机的短暂对齐确认，但没有转向动作，C++ 与 GZ 测试均单独检查这一行为。

同样，45°斜行后沿原路退回可以保持 45°轮向。若只把平移速度取反而保留角速度，不能保证所有轮速仅需取反，必须重新计算四个局部速度向量。只有 `(vx, vy, wz)` 整体取反，所有局部速度才整体取反。

机械转角累积取决于轮组相对车体的方向变化；车体持续原地旋转不使舵轮无限旋转。即便每次停稳后再选择最短转角，多次离散选择也可能逐渐接近限位，因此静止选解同样需要余量约束。

## 时间与失效处理

- 输入要求 `TwistStamped`，坐标系必须为 `base_link`。拒绝陈旧、明显未来、非有限值和不支持轴的指令，并制动。
- `/joint_states` 必须包含四个转向位置、四个实际转向速度与四个驱动角速度；超出硬限位、非有限、缺失或超过 0.2 s 的反馈不会作为有效控制依据。
- 控制定时器检查仿真时钟。暂停仿真不积分，时间倒退或过大的时间跳变清除旧状态。
- 指令正常超时采用减速停车；反馈失效采用立即发送零驱动目标的应急路径，不保证该应急路径满足正常加速度限制。
- 仿真启动器在运动节点退出或底层控制器激活失败时关闭仿真，防止留下持续执行旧指令的模拟底盘。此机制不是实车硬件看门狗；实车接入必须有独立驱动器超时保护。

## 验证方法与解释

控制核心使用独立 C++ 测试检查运动重建、机械限位选解、正反转、零速保持、统一限速、实际停稳门控、连续/停车切换、转向速度与加速度、高速偏差门控和异常配置。

ROS 边界测试使用合成关节反馈，验证陈旧/未来时间、错误坐标系、NaN、不支持轴、反馈丢失、恢复后旧指令清除和超时停车。它不替代 GZ 物理验证。

GZ 验证先等待稳定行驶，再在约 2 s 测量窗口内，以消息实际时间差计算理论位移，并与独立真值比较。覆盖前进、横移、斜行、原地旋转、组合运动和倒车；另测连续小转向、停车对轮、超时停车及 20 km/h 直线目标。

首阶段功能门限为位置误差 <0.15 m、航向误差 <0.12 rad；最高直线速度误差 <0.15 m/s。这些是低速功能回归门限，不是巡检或实车精度指标。精细轨迹跟踪和融合定位尚未实现，旋转/组合运动可能因接触模型产生明显误差。

## 已知边界

`gz_ros2_control` 默认转向位置与驱动速度接口使用理想关节伺服。URDF 中已声明力矩和速度限值，但本阶段没有真实电机闭环、减速器、驱动器力矩饱和或电气热模型；不能用当前结果证明 65 kg 实车在给定电机下达到 20 km/h，也不能证明原地转向力矩足够。

尚未实现三维融合定位、轮式里程计输出、坡面验收、悬挂、实际线阵图像、高亮补光、巡检规划与避障。模型外形仅大致参考用户图片，机械参数仍待实车方案确认。

## 参考

公开实现核对（2026-09-05）：

- WPILib 的 `SwerveModuleState.optimize` 通过半圈等价变换及驱动反向减少转向量；它本身不管理本项目这种未取模的有限机械行程。
- PathPlanner 的 `SwerveSetpointGenerator`（说明中注明源自 Team 254 的版本）从上一指令状态向目标车体速度共同插值，并同时约束模块转向速率、驱动速度/力矩和摩擦。在所有模块的运动方向都需大幅翻转时可先生成停车过渡；单轮零速与转向有单独处理。不能把“最短角选择”当成这一完整算法。
- AgileX Ranger 公开 ROS 驱动按模式向底盘发送速度与转向参数。平行模式的速度符号支持反向运行，但公开驱动没有完整的底层八电机切换逻辑，不能据此推断其固件的停稳判据和硬限位策略。

后续若要减少当前保守停车、保证连续过渡的严格刚体一致性，应在有限转角管理之外实现车体速度空间的联合指令生成，并在真实电机与轮胎参数确定后加入力矩和摩擦约束。当前不宣称已完成这些能力。

## 扩展序列验收

当日收尾：已实际使用 Mesa D3D12（NVIDIA RTX 5080）打开 GUI，确认相机 FOLLOW 目标为 `agv`；两项默认设置已写入启动配置及项目 `AGENTS.md`。八方向平移与正反原地旋转各发送 10 秒仿真时间指令（包含制动、对轮），十项结束均处于 DRIVE，最后确认 HOLD 且四轮驱动速度为零附近；记录见 `results/omnidirectional_demo.json`。演示后已关闭 GZ 和相关控制进程。

后续可从第二阶段线阵相机及高亮条形 LED 成像建模继续，具体任务以用户下一次指示为准。当前相机和 LED 仍仅有安装结构，第一阶段的控制能力边界见上文。

2026-09-05：45°和 −60°斜向沿原路退回时，实际轮向变化小于 1e-10 rad；此数值来自理想仿真，表示未进行转向动作。两个方向各进行了 22 s、0.2 rad/s 的运动方向变化试验，均出现一次限位前重配置，最大实际机械角约 174.8°，结束时均恢复 DRIVE。单次反馈角度变化约不超过 0.012 rad，未出现跨半圈目标被瞬时执行。

C++ 测试还覆盖了缓慢让单轮通过零速而其余轮子继续驱动、无条件回零的反例、静止最短解必须保留限位余量，以及原地旋转不积累机械转角。这里只证明明确列出的序列，不等于穷尽全部指令和地面状态。

现行限位余量修订：±190°硬限位、±185°软限位；静止目标总计保留8°硬限位余量，即从软限位再留3°，允许目标至±182°。上文10°软限位预留为历史设置。连续运动动态公式中的固定项相应改为3°，仍叠加转向制动距离和一个控制周期。见[恢复直行检查](../../issues/STEERING_SPIN_RECOVERY.md)。
